# Implementation Plan: 邮件报告可靠性与阅读工作台

## Overview

修复已确认的报告、来源、链接与时间问题，加入可撤销的本地已读名单，并把前端整理为适合每日查看邮件的响应式工作台。邮件服务器始终保持只读。

## Architecture Decisions

- 本地已读是独立记录：仅影响本应用的报告与后续扫描，不调用 IMAP 写入；移除记录后，同一封仍未读的邮件可以重新纳入报告。
- 报告快照保存链接的 AI 摘要、接收时间和排序后的项目，旧报告保持不变。
- 使用 IMAP `INTERNALDATE` 作为实际接收时间；邮件头 `Date` 只保留为发送时间。
- 同域未知来源在待确认前按域名合并，AI 提议只作为显示名；已有来源或类别不会再次建议。
- 链接只接受 `https` / `http`，其余协议在解析边界丢弃；模板仍使用自动转义。

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| IMAP 服务器未返回 `INTERNALDATE` | 接收时间缺失 | 仅在缺失时退回邮件头日期，并在数据模型中保留两者语义。 |
| AI 链接摘要成本上升 | 中 | 每封邮件最多发送少量安全链接，复用同一次分析调用。 |
| 旧 SQLite 库缺少新表 | 中 | 使用现有 `create_all` 添加新表；新字段采用可迁移的独立表。 |
| 真实邮件内容长度不稳定 | 中 | 浏览器使用种子测试数据验证长文本、空数据与窄屏布局。 |
